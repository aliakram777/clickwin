# Agent fabrikası, çoxagentli axın və real AI runtime (Mərhələ 17)

NAYMERA ixtisaslaşmış agentlər yarada, idarə edə və komanda kimi işlədə bilər. Hamısı mövcud təhlükəsizlik qatlarının **üzərindədir** (Company → Orchestrator → Effect Broker → Gate / Approval / Ledger); onları keçmir.

## Rollar (`agents/agent_roles.py`)
Proqramçı, Veb dizayner, Android developer, Video creator, Araşdırmaçı, Test mühəndisi, Data analyst, Layihə meneceri. Hər şablon: ixtisas, vəzifələr, **sistem təlimatı** (etibarsız məlumat və təsdiq qaydaları daxilində), icazə siyasəti, tapşırıq növləri, elan olunan alətlər (**hamısı `not_configured`**), yaddaş siyasəti (Cloud-a ötürmə defolt yox, yazma yalnız `result`/`note`).

## Agent (`agents/agent_factory.py`)
Unikal `agt_…` ID və ad, rol, ixtisas, sistem təlimatı, icazələr, **ayrı iş sahəsi** (`workspaces/<id>/`), büdcə limiti, tapşırıq siyahısı, yaddaş siyasəti, status (`active/stopped/archived/deleted`), hesabat. Hər əməliyyat (qəbul və rədd) audit jurnalındadır; sirr jurnala düşmür.
- **Yaradılış:** NAYMERA (sistem) yalnız **məhdud** agent yaradır: `read_files`, büdcə **0 AZN**, ötürmə yox (`Company.register_baseline_agent`). Sahib şablon daxilində `write_files/run_tests` (və yalnız `web_designer/android_developer/video_creator` üçün `publish`, `sensitive_ok` ilə) verə bilər. Pul və xarici hesab icazəsi heç bir şablonda yoxdur. Limitlər: ümumi/rol üzrə agent sayı, növbə uzunluğu; sahib avtonom yaradılışı söndürə bilər.
- **Agent özünü artıra bilmir:** `AgentHandle` yalnız `submit_result`, `handoff`, `request_permission`, `info` verir. İcazə **sorğusu** yalnız qeyd olunur; həll yalnız sahibdədir (`resolve_request`). Büdcə tavanı (`global_budget_cap`, defolt 0) yalnız sahib tərəfindən qaldırılır.
- **Həyat dövrü:** `stop` (reversible; effektiv icazələr boşaldılır), `restart` (əvvəlki səlahiyyəti bərpa edir, yenisini vermir; sahibin dayandırdığını yalnız sahib), `archive` (geri qayıtmaz), `delete` (yalnız sahib, yalnız arxivlənmişi; audit saxlanılır). Ardıcıl uğursuzluqda (3) agent sistem tərəfindən avtomatik dayandırılır.
- **Tapşırıq:** `assign` — rol növü, tutulan icazə, xərc (agentin `max_task_cost`, büdcə, 0 AZN), ölçü, sirr yoxlanır; `op_id` ilə idempotentdir.
- **Agentlərarası ötürmə:** `Company.handoff` səlahiyyəti (`delegate_to`, tutulan icazə, xərc) + payload yoxlaması: sirr rədd, ölçü limiti, təlimat bənzərliyi **işarələnir**, mətn `<untrusted_agent_output>` blokuna bükülür; dərinlik və dövrə nəzarəti; dayandırılmış agent ötürə bilməz.

## İcra (`agents/agent_runtime.py`)
`AgentDispatcher.execute` tapşırığı **atomik** tutur (təkrar icra yoxdur), `Orchestrator.execute(Task(agent=…))` ilə Broker/Gate/Ledger yoluna verir; həssas icazə (`publish`) Gate-də **sahib təsdiqi** gözləyir (`awaiting_approval`), təsdiqdən sonra EYNİ `op_id` ilə davam edir. `AgentLLMRunner` yalnız **mətn** alır (HybridRouter, AUTO/CLOUD/LOCAL); alət, fayl, şəbəkə, ödəniş, nəşr çağırışı yoxdur. Nəticə yoxlanır (ölçü, sirr, boşluq; təlimat bənzərliyi işarələnir) və agentin hesabatı yazılır. `prefetch` müstəqil tapşırıqların AI mətnini **paralel** alır (yan təsirsiz); icra/qeyd ardıcıldır.

## Çoxagentli axın (`agents/team.py`)
`TeamPlanner` məqsədi mərhələlərə bölür (qaydalar; LLM planı yalnız TƏKLİFdir: ciddi JSON, rol allowlist, DAG, LLM icazə seçə bilməz). `TeamRunner` agentləri seçir/yaradır (məhdud), asılılığı olmayan mərhələləri paralel generasiya edir, asılılıqları ardıcıl icra edir, uğursuz mərhələni eyni roldakı başqa agentə **bir dəfə** ötürür, əvəzedici yoxdursa asılı mərhələləri `skipped` edir, nəticələri yoxlayıb **yekun məhsul** (`FinalProduct`) və CEO üçün hesabat (`render_report_az`) qaytarır. Eyni plan təkrar işə salınsa heç nə iki dəfə icra olunmur. Plan xərci büdcə tavanını aşırsa başlamır. Həssas mərhələ üçün agent avtomatik yaradılmır.

## Məhsul bünövrəsi (`agents/builders.py`)
Website Builder, App Builder, APK Builder, Video Studio interfeysləri: **hamısı `not_configured`**, `plan()` deterministik SİMULYASİYA planı (planning → build → release), `build()` həmişə `NotConfigured`. Nəşr/imzalama/deployment mərhələləri `needs_approval` və `owner_only`; APK üçün Android SDK məhdudiyyəti və imzalama açarının sahibdə qalması qeyd olunur. `to_team_plan` yalnız planlaşdırma mərhələsini çoxagentli plana çevirir.

## Real AI runtime (`agents/providers.py`, `runtime/`)
OpenAI-uyğun provayder adapteri (nəqliyyat inyeksiya olunur; `agents/` şəbəkə kodu daşımır), real nəqliyyat `runtime/transport.py` (yönləndirmə yox, ölçü limiti, timeout). Endpoint siyasəti: Cloud yalnız HTTPS + ictimai DNS adı; şəxsi server loopback/özəl şəbəkə (HTTP) və ya TLS. `runtime/env.py` mühit dəyişənlərindən mühərrik qurur (`.env.example`): real Cloud yalnız **açar + baza URL + model + büdcə limiti > 0 + qiymətlər + xərc kitabı** olduqda `ready` olur (əks halda `not_configured`, səbəb göstərilir), istifadə üçün yenə `cloud_paid_use` razılığı lazımdır. Açar yalnız `Secret` ilə serverdə oxunur; repr/log/xəta mətnində yoxdur. Server: `python3 tools/serve.py`.

## Təhlükəsizlik möhkəmləndirməsi (audit F-1, F-2, F-3)
- **F-1 şəxsiyyət və imtiyaz:** `Principal` yalnız iddiadır; yalnız imzalı etibarnamə qəbul olunur (indi asimmetrik Ed25519, aşağıdakı «Təhlükəsizlik sərhədi» bölməsinə bax; ilkin HMAC həlli əvəz olunub). Özü yaradılmış `Principal(...)` `forged_principal` ilə rədd edilir; yoxlayıcı qurulmayıbsa imtiyazlı əməliyyatlar `owner_auth_unavailable` ilə BAĞLIDIR.
- **F-2 təsdiq = icra:** təsdiqə və icraya EYNİ giriş (`approval_input`: mətn, agent/növ, mətn və agent təlimatının SHA-256-sı) verilir; Broker bu girişin hash-ini təsdiqə bağlayır. İcraçı yalnız həmin girişdən istifadə edir (verilənlər bazasından yenidən oxumur) və modelə getməzdən dərhal əvvəl hash/agent/növ/təlimat/vəziyyət uyğunluğunu yoxlayır; uyğunsuzluq icranı dayandırır. Tapşırıq mətninin hash-i yaradılışda saxlanır (`prompt_sha`), dispetçer hər icradan əvvəl yoxlayır. Həssas icazəli tapşırığa yaddaş konteksti əlavə edilmir (təsdiqlənən mətn = modelə gedən mətn). Təsdiq tək istifadəlik/hash-ə bağlıdır (təkrar və başqa tapşırığa köçürmə rədd edilir).
- **F-3 LLM xərci = agent büdcəsi:** agent sorğusu `SpendScope` ilə işarələnir; `GuardedLLM` hər ödənişli sorğudan ƏVVƏL Ledger-də AGENTİN adına və sabit `llm:agt:<tapşırıq>` op_id ilə rezerv edir (agent limiti = Company büdcəsi, varsa ümumi limit və LLM-ə ümumi tavan eyni tranzaksiyada). Büdcə 0 isə router ödənişli mühərriki heç yoxlamır (`allow_paid=False`) və GuardedLLM də ayrıca rədd edir. Təkrar op_id ikinci dəfə ödənilmir; hesablaşma uğursuzdursa nəticə QAYTARILMIR, rezerv saxlanılır və sahib uzlaşdırması üçün işarələnir (naməlum xərc); real provayder agent əhatəsində Ledger-siz bağlıdır. `cloud_paid_use` razılığı və qlobal büdcə yoxlamaları saxlanıb.

## Təhlükəsizlik sərhədi (audit A-1..A-6)
**İmza modeli.** Etibarnamələr Ed25519 ilə imzalanır (`agents/factory_auth.py`, `cryptography` kitabxanası; `requirements.txt`). Şəxsi açar YALNIZ `TrustedSigner`-in bağlanışındadır (etibarlı bootstrap); atribut kimi saxlanmır, `pickle` qadağandır. Fabrik, `Company`, `AgentHandle` və `Keyring` yalnız açıq açarları (yoxlama) tanıyır. İmza verən obyektlər rola xasdır və dəyişdirilə bilməz: `SystemIssuer` (yalnız `system`), `DispatcherIssuer` (yalnız `dispatcher` şəxsiyyəti və `DispatchAuthorization`), `OwnerIssuer` (yalnız `from_step_up(qəbz)`; ixtiyari `owner_id` qəbul edən metod yoxdur), `MockOwnerIssuer` (yalnız test).

**Agentə baxan səthin daraldılması.** `AgentHandle` nüvəyə, `Company`-yə, icra fasadına və ya imza obyektinə atribut istinadı saxlamır (`__slots__`, dörd dar funksiya). Nüvə (`_Core`) yalnız oxu üzünü (`CompanyView`) və `Keyring`-i saxlayır; `Company.admin` yalnız `FactoryControl/FactoryAdmin` fasadlarına xas `_Privileged` obyektindədir. `FactoryRuntime` səlahiyyət VERMİR. Testlər obyekt qrafını (atribut, `__slots__`, konteyner, `__closure__`, `__self__`) gəzərək agentə baxan istinadlardan imza obyektinə, şəxsi açara, `Company`/`CompanyAdmin`/fasadlara çatılmadığını yoxlayır (müsbət nəzarətlə: analiz alətinin tapa bildiyi də göstərilir).

**Company müstəqil yoxlayır.** `Company(..., verifier=Keyring)`: hər imtiyazlı əməliyyatda (qeydiyyat, səlahiyyət, büdcə, dayandırma, ləğv, şöbə xərci) ilk addımda kimlik yoxlanır (agent növü, imza, açar/etibarnamə ləğvi, vaxt, rol). Yoxlayıcı yoxdursa `owner_auth_unavailable`. Autentifikasiyasız çağıran agentin mövcudluğunu belə öyrənmir.

**Hərəkətə bağlı bir-dəfəlik səlahiyyət.** `DispatchAuthorization`: `task_id`, `agent_id`, `run_op`, `op_id`, `attempt`, `action` (`submit_result` | `fail` | `await_approval` | `note_success`), `key_id`, `issued_at`, `expires_at` (≤ 300 s; defolt 60 s), `nonce`, imza. Yalnız etibarlı dispetçer imzalayır; fabrik yoxlayır, tapşırıq vəziyyətinə baxır (`submit_result/fail/await_approval` → `running`, `note_success` → `done`) və `nonce`-u bazada istehlak edir (təkrar → `dispatch_authorization_replayed`). Uğursuzluq sayğacı yalnız `running → failed` keçidi həqiqətən baş verəndə artır; tamamlanmış/təsdiq gözləyən/uğursuz tapşırıqda səlahiyyət keçmir; `note_success` təkrarı sayğacı sıfırlaya bilmir. Avtomatik dayandırma dispetçerin sistem şəxsiyyəti ilə `control.stop` vasitəsilədir.

**Sahib şəxsiyyəti = step-up.** `api/auth.py` `verify_proof` indi bir-dəfəlik `StepUpReceipt` qaytarır (server bazasında 128-bit id, cihaz/əməliyyat bağlılığı, 120 s ömür). `api/owner_gate.OwnerGate`: `challenge(device, operation, subject, hash)` yalnız `factory:` prefiksli əməliyyat üçün nonce verir; `authenticate(...)` cihazın Keystore imzasını yoxlayır, qəbz `consume_receipt` ilə YALNIZ BİR DƏFƏ və yalnız `factory:` növü üçün qəbul olunur və 120 s ömürlü sahib etibarnaməsi (`channel="stepup:<cihaz>"`) verilir. Adi təsdiq step-up-ı, təkrar, vaxtı keçmiş, ləğv olunmuş cihaz, başqa əməliyyat/subject və özü qurulmuş qəbz sahib etibarnaməsinə çevrilmir.

**İstehsal bootstrap-ı** (`runtime/factory_bootstrap.py`, `tools/serve.py`, `api/bootstrap.build_app(trust=...)`): `load_signing_config(env)` → `TrustAnchor` (şəxsi açar yalnız burada) → `Company(verifier=anchor.verifier)` → `anchor.build_factory(...)` `FactoryStack` qaytarır: `view`, `owner_gate`, `admin` (yalnız imzalı sahib ilə işləyir), `dispatcher`, `team`, `agent_handle`. İmza obyektləri, `Company.admin`, `FactoryControl`/`FactoryRuntime` stack-də YOXDUR. Açar yoxdursa `build_app` fabrik qurmur və `Company` imtiyazlı əməliyyatları bağlıdır; qismən/zəif konfiqurasiya `serve.py`-də açıq xəta ilə dayandırır.

**Açar yaratma və konfiqurasiya (yalnız server mühiti).**
```bash
python -c "from agents.factory_auth import generate_signing_seed as g; print(g())"   # 32 təsadüfi bayt (secrets), URL-təhlükəsiz base64, 43 simvol
export NAYMERA_SIGNING_KEY=<çıxış>          # şəxsi açar: yalnız server mühiti/sirr meneceri; repoya, APK-ya, loqa YAZMAYIN
export NAYMERA_SIGNING_KEY_ID=k-2026-11      # aktiv açar id-si (3-40 simvol)
export NAYMERA_VERIFY_KEYS=k-2026-10=<köhnə açıq açar base64>   # rotasiya: yalnız açıq hissə
export NAYMERA_REVOKED_KEYS=k-2026-09        # kompromis: ləğv olunmuş açar id-ləri
```
Açar tam 32 bayt olmalıdır; təkrar/ardıcıl/az fərqli baytlı və ya oxunaqlı mətn (parol kimi) açar rədd edilir (bu bariz zəifliyi tutur, təsadüfilik sübutu deyil). **Rotasiya:** yeni açar yarat → onu aktiv et (`KEY_ID` dəyişir), köhnənin açıq açarını `NAYMERA_VERIFY_KEYS`-ə əlavə et → ən uzun etibarnamə ömrü (900 s) keçəndən sonra köhnəni sil. **Kompromis:** köhnə id-ni `NAYMERA_REVOKED_KEYS`-ə yaz (bu açarla imzalanmış HƏR etibarnamə dərhal rədd edilir) və yeni açar yarat; proses-daxili `Keyring.revoke_key/revoke_credential` də var. Etibarnamə ömürləri: sahib 120 s, dispetçer 120 s, sistem 300 s, səlahiyyət 60 s (yuxarı hədd: 900/300 s).

## Agent izolyasiya sərhədi (audit B-1/B-2 PR #20; H-1..H-4, M-1..M-4 PR #21)
**Əsas qayda:** agent kodu etibarlı serverlə EYNİ prosesdə işlətmək üçün nəzərdə tutulmayıb. Proses-daxili `AgentHandle`/`factory.handle()` SƏRHƏD DEYİL (bağlanışlar, `Company`/DB bağlantıları və reyestr çatandır; bunu sınaq müsbət nəzarətlə göstərir). Agent kodu `runtime/agent_gateway.py` `AgentGateway` ilə AYRI OS prosesində işləyir.

**Arxitektura.** Server `runtime/agent_worker.py`-ı `python -I -S -B`, boş mühit (`env={}`), boş iş qovluğu, `close_fds` və yalnız iki irsi fd ilə başladır: AF_UNIX `socketpair` ucu və sessiya açarı borusu. İşçi yalnız stdlib işlədir və depodan heç nə idxal etmir; ona yalnız `agent_worker.py`, `agent_wire.py` və agent proqramının surəti veriləcək şəxsi qovluq görünür. Agent proqramı `main(client)` funksiyası ilə `AgentClient`-i alır.

**RPC (minimum).** Yalnız `hello`, `info`, `request_permission`, `handoff`. Agent id sessiyaya SERVER tərəfindən bağlanır (müştəri göndərə bilmir; əlavə arqument `bad_args`). Ciddi arqument sxemi (tip/ölçü/regex), hər sorğuda agent hələ `active`-dirmi yoxlanır (dayandırılan agentin sessiyası bağlanır), sorğu limiti, naməlum əməliyyat/pis çərçivə/pozuntu limiti -> proses öldürülür. Cavab yalnız JSON proyeksiyadır (obyekt/istinad ötürülmür; `info` yalnız `agent_id, name, role_id, title, department, status, permissions`). Heç bir imtiyazlı əməliyyat (tapşırıq vəziyyəti, hesabat, büdcə/səlahiyyət, açar, reyestr, SQL, `claim/fail/note_success`, sahib əməliyyatları) RPC-də MÖVCUD DEYİL.

**Autentifikasiya.** Hər çərçivə sessiyaya xas 32 baytlıq təsadüfi açarla HMAC-SHA256 (istiqamət + ciddi artan sıra nömrəsi + gövdə) daşıyır: saxta/dəyişdirilmiş/təkrar/yenidən-sıralanmış/başqa-istiqamətli çərçivə sessiyanı bağlayır. Açar ayrıca borudan bir dəfə oxunur. Kanal şifrələmir (yerli socketpair) və AF_UNIX `socketpair` üçün `SO_PEERCRED` faydasızdır (hər iki uc yaradıcının kredensiallarını daşıyır); autentifikasiya fd irsiliyi + HMAC-ə əsaslanır.

**OS səviyyəsi (nə var).** Server root-dursa və `uid_pool` (defolt `62000–62255`, NAYMERA-ya AYRILMIŞ aralıq; passwd-da olan və ya başqa proses işlədən uid atlanır) varsa HƏR SESSİYAYA unikal uid/gid verilir. İşçi (hələ root ikən, agent kodundan əvvəl): `unshare(CLONE_NEWNET)` (alınmazsa dərhal çıxır), `setgroups([])`+`setgid`+`setuid`, geri qayıtmanın mümkünsüzlüyü yoxlanır, `PR_SET_NO_NEW_PRIVS`, `PR_SET_DUMPABLE=0`, rlimit-lər (CORE=0, NOFILE=64, CPU=60 s, FSIZE=10 MiB, AS=1 GiB, NPROC=32: unikal uid sayəsində hər sessiyanın proses ağacı üçün real tavan), umask 077, **seccomp filtri** (yalnız x86_64: ptrace, process_vm_*, mount/umount/pivot_root/chroot, unshare/setns, `clone` ad-sahəsi bayraqları, clone3, bpf, perf_event_open, keyctl, kexec/module, io_uring, mount API, mknod və s. EPERM/ENOSYS; x32 ABI öldürülür). Sessiya qovluqları gateway-in şəxsi bazasında (`0711`, siyahı alına bilməz), sessiya qovluğu `root:<gid> 0750`, iş qovluğu yalnız sessiya uid-inə `0700`: sessiyalar bir-birinin qovluğunu siyahılaya/oxuya bilmir. Server özü `PR_SET_DUMPABLE=0` edir; `build_app` data qovluğunu 0700 edir.

**Server tərəfli yoxlama (işçinin iddiasına DEYİL, `/proc`-a əsaslanır).** `hello`-dan əvvəl (agent kodu başlamamış) server oxuyur: `PPid`==server, `Uid/Gid` dörd sahə də sessiya uid/gid-ə bərabər, `Groups` boş, `CapInh/Prm/Eff/Amb`=0, `NoNewPrivs=1`, `Seccomp=2`, şəbəkə namespace-i (`/proc/<pid>/ns/net` serverinkindən FƏRQLİ və `/proc/<pid>/net/dev`-də yalnız `lo`), dumpable=0 (`/proc/<pid>/environ` sahibi root), `/proc/<pid>/limits` (core=0 və qalanı tələb olunan həddən çox deyil). Tələb olunan xassə təsdiqlənmirsə `hello` cavabsız qalır, proses öldürülür (`isolation_unverified:<xassə>`) və agent kodu HEÇ VAXT işləmir. Şəbəkə namespace-i (`require_net_isolation`, defolt True) və seccomp (`require_seccomp`, defolt True) alınmazsa sessiya AÇILMIR (məs. CAP_SYS_ADMIN-siz root konteyner, x86_64-dən başqa arxitektura). `SessionResult.isolation` yalnız server-yoxlanmış xassələrdir; işçinin hello bayraqları ayrıca `reported`-dədir (etibarsız, diaqnostika). `security_boundary` yalnız izolyasiya rejimində və hamısı təsdiqlənibsə True.

**Proses ağacı və təmizlik.** Bütün giriş/çıxış qeyri-bloklayıcıdır (`selectors`/epoll: fd ≥ 1024 problemi yoxdur); yazma buferi limitlidir (128 KiB; cavabları oxumayan agent `backpressure` ilə kəsilir), hər `pump()` ödəniş müddətini tətbiq edir, bağlama (`killpg` + sessiya uid-inin BÜTÜN proseslərinin SIGKILL-ı: fork/setsid qaçışı daxil) `pump()`-ı bloklamır, qalıq proses varsa uid karantinaya alınır. İşçi çıxdıqdan sonra soketi saxlayan uşaqlar qalıq çərçivələr boşaldıldıqdan sonra təmizlənir (`survivors_killed`). JSON gövdəsinin iç-içəliyi (≤6) və ölçüsü (≤64 KiB) ayrışdırmadan ƏVVƏL yoxlanır; gözlənilməz xəta yalnız həmin sessiyanı bağlayır. Ölü server prosesindən qalan baza qovluqları sonrakı gateway tərəfindən silinir.

**Nə YOXDUR (məhdudiyyətlər).** Bu tam OS sandbox DEYİL:
- `allow_insecure_same_uid=True` rejimi (root olmayan server) TƏHLÜKƏSİZLİK SƏRHƏDİ DEYİL: agent serverlə EYNİ istifadəçidir, onu öldürə, DB fayllarını oxuya/yaza, şəbəkəyə çıxa və öz uşaq proseslərini saxlaya bilər; unikal uid, namespace və proses ağacı təmizliyi YOXDUR. Defolt olaraq BAĞLIDIR (sessiya açılmır), yalnız açıq seçimlə işləyir və nəticədə `security_boundary=False`, `isolation["uid_unique"]=False` göstərilir. Yalnız test/inkişaf üçündür.
- Mount/PID/IPC/user namespace, cgroup (yaddaş/CPU limiti per-sessiya), fayl sistemi `pivot_root` YOXDUR: agent unikal uid ilə belə dünyaca oxunan yollara (`/etc/passwd`, depo kodu, `/proc/<pid>/cmdline`) və dünyaca yazılan yollara (`/tmp`, `/dev/shm`) çata bilir; PID namespace olmadığı üçün başqa proseslərin mövcudluğunu görür (siqnal göndərə bilmir). AF_UNIX pathname soketləri fayl icazələri ilə qorunur (namespace onları bağlamır).
- seccomp siyahısı qara siyahıdır (qadağan olunmayan sistem çağırışları işləyir) və yalnız x86_64-də həyata keçirilib/sınanıb. dumpable və NoNewPrivs/limitlərin bir hissəsi `/proc` dolayı əlamətləri ilə yoxlanır (dumpable: `environ` sahibi).
- Konteyner init-i zombiləri götürməzsə ölü proseslər `RLIMIT_NPROC`-u tutur: gateway belə uid-ləri təkrar vermir (pool tükənə bilər); init düzgün olmalıdır.
- Server uid_pool-u bir hostda yalnız bir gateway üçün nəzərdə tutur (paylaşılan hovuz konfliktləri üçün hələ koordinasiya yoxdur).
- RPC `handoff` agentə digər agentlər üçün növbəli tapşırıq yaratmağa icazə verir (Company ötürmə qaydaları + sahibin verdiyi `delegate_to` ilə məhdud, icra yalnız Orchestrator/Broker/Təsdiq yolundadır); `request_permission` yalnız sorğudur (sahib həll edir).
- Server sorğuları BİR-iplikli emal edir (`AgentGateway.pump()` DB bağlantılarını yaradan iplikdən çağırılmalıdır); `Company`/Registry/Ledger bağlantıları hələ thread-bound-dir (audit B-5, açıq).
- Agent proqramları operatorun `program_root` qovluğundakı etibarlı fayllardır (ad regex, symlink/yol yoxlaması); agent özü proqram yükləyə bilmir. Yoxlama-kopyalama arasında yarış yalnız `program_root` etibarsız istifadəçilərə yazıla bilirsə mümkündür (qadağandır).
- `stdout/stderr` ETİBARSIZ agent mətnidir (16 KiB-a kəsilir).

**Konfiqurasiya.** `anchor.build_factory(..., program_root=..., agent_isolation={...})` / `build_app(..., agent_isolation={...})`. Defolt: `{"uid_pool": (62000, 62256)}`, `require_net_isolation=True`, `require_seccomp=True`, `allow_insecure_same_uid=False` (root olmayan serverdə sessiya `IsolationError` ilə RƏDD edilir). Digər parametrlər: `limits`, `max_sessions`, `max_requests`, `max_violations`, `max_outbuf`. İstifadə: `stack.agents.run_session(agent_id, "proqram.py", args=[...], timeout_s=...)`, `stack.agents.close()`.

**Keyring (B-1/2).** `Keyring` yalnız yoxlamadır (`check_*`, `key_ids`, `frozen`); açar əlavə etmək, ləğv və dondurma YALNIZ `take_control()` ilə BİR dəfə alınan `KeyringControl`-dadır, onu `TrustAnchor` dərhal götürür. Bootstrap `verify_keys` + `revoked_keys`-i yüklədikdən sonra `freeze()` edir: yeni açar əlavə/dəyişdirmə (hətta daxili `_add`) `keyring_frozen` ilə rədd olunur. Ləğv (daraltma) yalnız etibarlı control-plane ilə: `TrustAnchor.revoke_key/revoke_credential`. (Proses-daxili `ring._keys[...] =` kimi birbaşa yaddaş yazısı qorunmur: bu yalnız etibarlı prosesdəki koda aiddir.)

**Paylama səthi (B-2).** `FactoryStack`: `view`, `owner_gate`, `console` (`OwnerConsole`: obyektdə yalnız təsadüfi `_token` simvol açarı var; funksiya default/closure/atributlarında `FactoryAdmin/Control`, `AgentFactory`, `Company` və bağlı metod YOXDUR, çağıran öz callable-ını ötürə bilmir; arxa uc modul reyestrindədir və eyni prosesdə `__globals__` ilə əlçatandır: bu proses-daxili sərhəd DEYİL), `dispatcher`, `team`, `agents` (`AgentGateway`). `agent_handle` və `admin` sahələri silinib. `dispatcher`/`team` etibarlı icra mühərrikləridir və fabrikə istinad saxlayır: onlar da agent koduna verilməməlidir.
